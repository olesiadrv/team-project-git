**🚀 Командний Проект: База Знань Курсу "Інженерія Програмного Забезпечення"**

Ласкаво просимо до нашого спільного репозиторію!
Мета цього проекту — імітувати реальний процес командної розробки, використовуючи Git та GitHub.

Ваше завдання: Кожен учасник створює файл, що містить опис однієї теми з курсу.

**🚦 Стратегія Гілок (Branching Strategy)**
Ми використовуємо спрощений Gitflow:
main: Завжди стабільний та готовий до релізу (Production). Не чіпаємо!
dev: Гілка інтеграції. Усі нові функції спочатку зливаються сюди.
feature/<назва>: Ваша індивідуальна робоча гілка.

**📝 Як працювати:**
Старт: Створюємо робочу гілку від dev.
_git checkout dev
git pull origin dev
git checkout -b feature/topic-5-versions_

Робота: Створюєте свій файл topic-5-versions.md та додаєте контент.
Збереження:
_git add .
git commit -m "feat: Add documentation for Topic 5 Version Control"
git push -u origin feature/topic-5-versions_

Фінал: Створюєте Pull Request з вашої гілки (feature/...) в гілку (dev).

**📋 Список Тем для Розробки (Оберіть одну унікальну тему!)**
Створюйте файл з назвою 
_topic-<номер>-<тема>.md._

**🛠️ Як вирішити Конфлікт (Merge Conflict)**
Конфлікт виникає, коли Git не може автоматично об'єднати зміни в одному місці.
Бачите конфлікт: Відкрийте конфліктний файл.
Знайдіть маркери:
<<<<<<< HEAD
Ваша версія коду
=======
Версія коду колеги
>>>>>>> <хеш_коміту>
Виправте: Залиште лише правильний код, видаливши всі маркери (<<<, ===, >>>).
>>>>>>> Зафіксуйте:git add <конфліктний_файл>
_git commit -m "fix: RESOLVED MERGE CONFLICT in <файл>"_
